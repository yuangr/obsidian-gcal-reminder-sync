# GCal Reminder Sync for Obsidian

[English](README.md) | 简体中文

将 Markdown 行内待办同步为 Google Calendar 事件，由 Google Calendar 发送通知。笔记仍保留在 Obsidian；日历会收到任务标题、时间和提醒设置。

## 2.0 升级须知

**插件与 Apps Script 必须一起升级。旧版公开 Webhook 没有独立鉴权，更新本地插件不会保护旧服务端。**

1. 备份笔记和插件配置，暂停旧插件。
2. 按下文部署新版服务端，设置共享密钥与固定日历 ID。
3. 安装新版 main.js、manifest.json，配置新的 URL、密钥和时区。
4. 执行“测试 Webhook 连接”。测试只读，不创建日程。
5. 迁移旧任务关联，再开启正常使用。确认升级完成后，停用仍可访问的旧版部署。

版本 2.0 需要 Obsidian 1.5.0+，桌面和移动端使用同一套逻辑。无需 npm 安装插件运行依赖。

## 功能与边界

- 输入触发词自动新建；编辑后更新；勾选完成后删除日程或关闭提醒。
- 支持 Reminder 的 (@日期 时间)、📅、⏰、⏳、🛫 和裸日期格式。
- 代码围栏中的示例、普通段落、已完成且未关联的任务不触发新建。
- 每条任务保留隐藏的任务 ID、事件 ID；同名任务分别关联。
- 网络失败有限重试，等待 2、10、30 秒，最多 4 次请求尝试。永久错误停止自动重试。
- 插件重新启动后，可恢复带唯一 ID 的未完成创建请求；Google 端重复请求只生成同一个事件。
- Pull 只处理当前笔记。请求期间移动行不会改错其他任务；遇到本地修改或查询失败，会保留本地内容。
- 远端删除的日程不会被普通编辑自动重建；手动同步可明确重建。
- 完成后取消勾选可重新启用提醒。删除过的事件会使用新的事件代次。
- Google Calendar 事件不是 Google Tasks 对象；手机通知依赖 Google Calendar 的通知权限、账号同步、设备设置及网络，不能保证百分百送达。
- Obsidian 关闭时插件不运行，尚未推送的新任务不会在后台自动同步。已经成功写入 Google 的事件由 Google 提醒。
- v2 防止单实例并发与重复创建；它不是多设备离线冲突自动合并系统。远端内容冲突需先 Pull 检查，或明确选择以本地覆盖。
- 删除整行/整个笔记不会自动删除已关联事件。需要先勾选完成并确认同步，再清理笔记。若任务在首次创建尚未返回时被删掉，插件会尽力清理该次新建事件。
- 无独立的逐任务提醒提前量语法；提前量和默认时长来自插件设置。

## 服务端部署

1. 打开 [Google Apps Script](https://script.google.com/home/start)，新建项目。
2. 将 google-apps-script/Code.gs 完整复制到 Code.gs。
3. 在左侧点击齿轮进入“项目设置”，勾选“在编辑器中显示‘appsscript.json’清单文件”（截图中“启用 Chrome V8 运行时”下方的第三个复选框）。然后返回脚本编辑器，在文件列表中打开 appsscript.json，用本项目 [appsscript.json](google-apps-script/appsscript.json) 的内容完整替换并保存。它声明 Calendar、外部请求权限和 Calendar v3 服务。
4. 保存 appsscript.json 后刷新编辑器，左侧“服务”下方应自动显示 Calendar。不要再点击“+”重复添加，否则会出现“服务标识符 Calendar 使用过多次”的错误。本项目清单已经包含唯一的 Calendar API v3 声明。如果清单保存后仍未显示服务，才使用“+”添加 Calendar API v3；此时应先删除清单中 enabledAdvancedServices 下原有的 Calendar 对象，再由界面添加，二者只能选一种。当前项目使用默认 GCP 时，启用服务会自动启用对应 API；只有切换到自定义 Google Cloud 项目时，才需要再到 Cloud Console 手动启用 Google Calendar API。
5. 在项目设置的“脚本属性”中添加：

| 属性 | 值 |
| --- | --- |
| SYNC_SECRET | 用密码管理器生成的至少 32 字符随机密钥；不要使用示例值、提交到 Git 或分享 |
| CALENDAR_ID | 固定目标日历的精确 ID，从 Google Calendar 设置 → 对应日历 → 整合日历获取 |
| LEGACY_EVENT_IDS | 仅迁移旧版时使用，见下一节；平时留空 |

建议新建专用日历。服务端仅访问 CALENDAR_ID，不再按名称模糊查找，也不会找不到时回退到主日历。

6. 部署 → 新部署 → Web 应用；执行身份选择自己，访问范围选择“所有人”。外部请求必须携带匹配的共享密钥；仅持有 URL 不再足够。
7. 授予脚本权限，复制 HTTPS /exec 地址。更新已有部署时，在“管理部署”中选择新版本。改变权限可能需要重新授权。

旧地址如果仍运行旧代码，依然存在原来的无鉴权风险；请在管理部署中停用不再使用的旧部署。

## 插件安装与设置

将 main.js 和 manifest.json 放入笔记库的 .obsidian/plugins/gcal-reminder-sync/，在 Obsidian 第三方插件中启用。两个文件足够，无需复制测试文件或 Apps Script 到插件目录。

配置以下项目：

| 设置 | 建议 |
| --- | --- |
| Webhook URL | 新版服务端的 HTTPS /exec 地址 |
| 共享密钥 | 与 SYNC_SECRET 完全相同 |
| 同步文件夹 | Vault 内相对路径；留空扫描所有 Markdown |
| 时区 | 多设备统一填写 Asia/Shanghai 等 IANA 时区；留空使用当前设备时区 |
| 默认时间 | 09:00 |
| 默认时长 | 30 分钟，可设 1–1440 |
| 提前提醒 | 默认 15；0 为准点，-1 关闭，最大 40320 |
| 完成动作 | 删除日程，或保留并关闭提醒 |

密钥存放在插件本地 data.json 中。不要公开该文件；如果同步插件配置到其他设备，密钥也会一起同步。服务端不保存笔记路径或正文，只管理日历事件。

配置完成后点击设置中的“测试连接”。测试成功只表示鉴权和日历访问正常，不代表手机通知设置已验证。

## 迁移 1.x 的任务

旧注释使用 iCalUID，例如 <!-- gcal: abc@google.com -->，没有事件归属标记。v2 默认拒绝修改这些事件，以免误操作无关日程。

1. CALENDAR_ID 必须指向旧事件实际所在的日历。若旧版曾回退到主日历，请先核实位置。
2. 将当前笔记需要迁移的旧事件 ID，逐个加入脚本属性 LEGACY_EVENT_IDS，以换行或逗号分隔。
3. 在 Obsidian 打开该笔记，执行“迁移当前笔记的旧版事件关联”，核对确认提示。
4. 服务端只接管允许清单中的事件；插件写入唯一任务 ID，并拉取远端内容。若当前任务有尚未推送的修改，请先备份比较。
5. 成功后清空 LEGACY_EVENT_IDS；已迁移事件凭归属标记正常工作。

无 ID 的旧 <!-- gcal-syncing --> 无法判断 Google 是否已经创建事件。手动执行“同步当前行”，按提示先核对日历，再确认重新创建。新版本产生的 pending 标记带唯一任务 ID，可自动恢复。

旧 calendarName 设置不再决定目标日历，改由服务端 CALENDAR_ID 固定；旧 syncedSignatures 不作为 v2 的同步成功依据。

## 任务示例

~~~markdown
- [ ] 部门周会 (@2026-09-25 14:30) !gcal
- [ ] 提交报表 ⏰ 2026-09-25 17:00 📅 2026-09-25 !gcal
- [ ] 购买礼物 📅 2026-09-26 !gcal
- [ ] 课程预习 ⏳ 2026-09-26 10:00 !gcal
- [ ] 换驾照 2026-09-27 10:00 !gcal
~~~

不同时间标记并存时按固定优先级解析：Reminder → ⏰ → 📅 → ⏳ → 🛫 → 裸日期。请避免一条任务写多个相互矛盾的提醒时间。Pull 保留日期格式，并写回具体时间；远端全天事件使用隐藏的 all-day 标记，避免被默认时间反复改写。

请不要把包含 gcal 注释的一行直接复制成新任务，否则它仍表示同一个任务。复制后移除该行所有 gcal 注释，再加触发词。

## 同步、冲突与恢复

- 新建：输入触发词后停顿，或执行“同步当前行”。
- 修改：自动防抖推送；开启“光标离开编辑行时立即同步”可提前触发。
- 失败：状态栏保留错误。可重试错误按退避间隔重试，永久错误或达到上限后需修正原因，再执行手动同步。
- 完成：操作与更新顺序执行；只有服务端确认成功才写入 done 标记。
- Pull：重新定位任务 ID。若笔记在等待期间变化，会跳过该任务；未同步本地修改也会跳过。
- 冲突：检查 Google 和笔记内容后决定保留哪边。若保留本地版本，手动“同步当前行”或“重试当前笔记全部已关联任务”会明确重新推送并覆盖远端对应字段；先备份需要保留的远端内容。
- 新设备：先 Pull 建立同步基准；没有基准的既有活动关联不会在启动时直接覆盖 Google。
- 回退版本：不建议让 1.x 客户端继续调用 v2；其请求缺少鉴权与协议字段，会被拒绝。

目前未提供重复任务规则、Google Tasks 同步、全部字段双向同步、跨设备自动冲突合并或离线后台服务。

## 开发与验证

只需 Node.js 18+，无第三方测试依赖：

~~~sh
npm test
npm run check
~~~

测试加载真实客户端和服务端代码，使用模拟 Obsidian/Google API，覆盖任务定位、在途编辑、完成与重开、幂等重试、查询/删除失败、时区、权限和旧版迁移。测试不访问真实账号。

发布前仍需在独立测试日历进行桌面/移动端验证：创建 → 修改 → Pull → 完成 → 重开，并确认手机端通知权限。模拟测试不能证明实际 Google 授权和手机通知已正常配置。
